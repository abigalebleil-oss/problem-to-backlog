# Company knowledge (shared by every team)

Fictional company standards. Every persona and initiative inherits these. Change them here once
and every team's output follows. Each line with an ID can be cited by the skill, and each ends
with the vetted source it came from.

## Definitions
- K-1: Milestone: a slice of the initiative committed for a specific release window that delivers user-visible value on its own [src: S-CO-1]
- K-2: Customer value delivery (CVD): one unit of work a team can finish within a sprint that a named user would notice, written as a user need with Given / when / then acceptance criteria [src: S-CO-1]
- K-3: Requirement: one testable "shall" statement about the system, derived from a finding or design element, verifiable by test, inspection, analysis or demonstration [src: S-CO-1]

## Delivery calendar
- K-4: Two releases per year (YYYY.1 in Q2, YYYY.2 in Q4); each release has six two-week sprints, and sprint 6 is reserved for verification and release activities [src: S-CO-2]
- K-5: Planning assumes one scrum team per initiative unless the PO states otherwise [src: S-CO-2]

## Definition of ready
- K-6: A CVD is ready when it traces to a requirement, has testable acceptance criteria, has no open blocking question, and every assumption it depends on is confirmed [src: S-CO-1]
- K-7: A requirement is ready when it has a verification method and its source finding or design element is cited [src: S-CO-1]

## Writing standard
- K-8: Requirements use "shall"; one behavior per requirement; numbers instead of adjectives [src: S-CO-3]
- K-9: Anything the AI proposes that no input states is marked [PROPOSED] and listed as an assumption for a human to confirm [src: S-CO-3]
